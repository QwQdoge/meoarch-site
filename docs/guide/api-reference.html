做应用需要的全部接口。基础地址 https://api.meoarch.org/v1。登录、令牌、流式对话的细节、错误码和额度见 Meo Account API；桌面应用怎么取得令牌见 原生应用接入。

仍在开发中，以线上实际行为为准。本页只列出路由和约定；没有写明的字段以实际响应为准，请不要依赖未写明的字段。

约定

  • 请求和响应都是 JSON（Content-Type: application/json），除非另有说明。请求体有大小上限，超过返回 413 request_too_large。
  • 错误响应是 { "error": { "code": "…" } }，请读 code 而不是文字。常见：400 invalid_request、401 unauthenticated、403 insufficient_scope、403 reauth_required、404（不存在，或不属于你）、405 method_not_allowed、409、503。
  • 别人的资源一律返回 404，不会是 403。每个受保护的查询都限定在当前账号。
  • 浏览器跨域调用只允许 https://account.meoarch.org 和 https://chat.meoarch.org，方法 GET, HEAD, POST, PATCH, DELETE, OPTIONS，请求头 Authorization, Content-Type, DPoP。
  • 被封禁或已删除的账号在认证后会被拒绝。

认证

身份方式scope
网页登录登录 Cookie不受限
原生或第三方客户端Authorization: Bearer <访问令牌>meo:read 允许 GET/HEAD，meo:write 允许其他方法

OAuth 2.1 的端点在 /v1/auth/*（授权码 + S256 PKCE）。POST /v1/auth/login 是 /v1/auth/sign-in/email 的兼容别名。注册、登录等可能需要 Cloudflare Turnstile 令牌，由服务端校验。

受保护的账号操作

下面这些不能只靠一个登录会话直接调用，需要一个新鲜的、限定用途的重新验证授权：change-password、link-social、unlink-account、two-factor/enable、two-factor/disable、two-factor/get-totp-uri、two-factor/generate-backup-codes、revoke-session、revoke-sessions、revoke-other-sessions。

/v1/auth/change-email 和 /v1/auth/delete-user 被直接禁用（use_account_api），请用 POST /v1/account/email 和 DELETE /v1/account。直接调用 /v1/auth/request-password-reset 和 /v1/auth/send-verification-email 同样被禁用（use_account_security_api），请用下面的账号接口。

重新验证

用途：account_security、admin、billing、delete_account。客户端可以发起重新验证，但永远不能自己生成或声明授权。

方法路径说明
POST/reauth/password证明当前密码，得到 {purpose} 的授权，600 秒有效
POST/reauth/totp证明一次性验证码，得到授权
GET/auth/reauth/methods当前账号可用的重新验证方式
GET/auth/reauth/status是否有一个新鲜的授权
POST/auth/reauth/start发起 Google/GitHub 重新验证，{provider, purpose}；回调必须对应同一个账号

请求 { "purpose": "account_security" }，响应 { "verified": true, "purpose": "…", "expires_in_seconds": 600 }。

账号

方法路径说明
GET/me当前身份（简要）
GET/account账号概览：资料、角色、数量、会员
GET PATCH/profile读取、修改资料
GET PATCH/settings读取、修改可编辑的偏好（只接受白名单里的字段）
GET/plans方案目录：free、plus、pro
GET/subscription当前订阅，只读（付费等级由服务端决定）
GET/linked-providers已绑定的登录方式，不含令牌
GET/security-events自己的安全记录
POST/account/activate一次性的人机激活，需要登录会话和 Turnstile 令牌
POST/account/email发起主邮箱修改（两步；需要重新验证）。新邮箱验证前保持待定，原邮箱会收到通知
POST/account/password给只用社交登录的账号添加初始密码（需要重新验证）
POST/account/security{action}：account_overview，或 revoke_registered_sessions（targetSessionIds ≤100 个，需要 account_security 授权）
POST/account/desktop-operations桌面客户端的账号操作交接
GET/account/export导出自己的账号数据
DELETE/account删除账号（需要 delete_account 授权并明确确认；会吊销会话和令牌）
POST/account/password-reset/request请求重置密码（带 Turnstile，不暴露账号是否存在）
POST/account/send-verification-email重发验证邮件（需登录，带 Turnstile）

DELETE/sessions/:id注销一个会话
DELETE/sessions/others注销除当前外的所有会话
DELETE/sessions注销所有会话

对话与消息

方法路径说明
GET/conversations按游标分页，只含自己的
POST/conversations新建对话
GET/conversations/:id/messages读取消息
POST/conversations/:id/messages追加一条有长度限制的消息

对话生成、图片、搜索

都是 POST，需要 meo:write（或网页登录），并使用你自己的模型连接（credentialId）；提供商密钥永远不会到客户端。

路径说明
/chat/prepare校验并组装一次对话请求（同意、个人上下文、技能、MCP 工具），不调用提供商。可选 environment：`{client: desktop\web\android, os, locale, timezone, device, role, thinking, webSearch, subagents, location}`，告诉模型它运行在哪里
/chat/stream与 prepare 同样的输入，流式返回模型的回答，格式见 Meo Account API
/images/prepare校验一次生成图片的请求
/images/generate生成图片；结果按提供商返回的原样给出，不会保存。请求体：credentialId、model、prompt（≤4000 字）、size、consent
/search/web服务端联网搜索，用来给一次对话提供依据
/fetch/web把一个网址读成文本或 Markdown，供 web_fetch 工具使用：只允许 http(s)，网址里不能带凭据，不能是本机或私有地址，只跟随同源重定向，限制大小和时间，只接受文本类内容；非 2xx 状态会原样返回而不是报错

模型连接

方法路径说明
GET/ai/credentials连接的元数据，永远不返回密钥
POST/ai/credentials创建一个加密保存的模型连接
PATCH DELETE/ai/credentials/:id修改、删除
GET/ai/credentials/:id/models发现该连接的模型（含能力），按连接缓存 5 分钟；修改连接后失效
POST/ai/credentials/:id/test测试连接
POST/ai/credentials/:id/test-image测试图片能力
POST/ai/provider-broker受同意约束的提供商操作（action 如 list_models、prepare_inference、invoke、deny_inference）
GET/ai/model-profiles账号的模型配置，以及角色目录（id、名称、用途、需要的任务和输入、准确度、影响、延迟、用量、说明）。服务端还没升级时返回 503 model_profiles_unavailable
POST/ai/model-profiles新建 {name, description?, roles?}；roles 把角色 id 对应到 {credentialId, model}。未知的角色、不属于你的连接会被丢弃并列在 warnings。最多 20 个
PATCH/ai/model-profiles/:id修改名称、说明，或合并 roles（null 清除一个角色）
DELETE/ai/model-profiles/:id删除
POST/ai/model-profiles/:id/activate设为账号当前使用的配置（至多一个）
POST/ai/model-profiles/generation-prompt{requirements} → {prompt, connections}：让模型起草配置所需的文字。客户端要通过正常的、需要同意的对话流程把它发出去
POST/ai/model-profiles/draft{text}（模型的回复）→ {draft: {name, description, roles, warnings}}，只校验，不保存
POST/ai/orchestration`{stage: router\plan\step\judge, message, thinking, …} → {prompt}`：多次调用才能完成一个回答的某个阶段所需的文字（router 选角色，plan 列步骤，step 执行一步，judge 给 0–100 打分）。客户端用对应角色的模型，通过需要同意的对话流程运行

PATCH DELETE/ai/memories/:id修改、删除

插件、MCP 和技能

对话里的工具调用受同意和批准约束，在服务端强制执行；可选的 MCP / 技能表没有准备好时返回 503 mcp_storage_unavailable。

方法路径说明
GET/ai/catalog/mcpMCP 目录
GET/ai/catalog/github-skill解析一个托管在 GitHub 的技能
GET POST/ai/plugins插件：列表、新建（kind：mcp、skills、bundle）
PATCH DELETE/ai/plugins/:id修改、删除
PUT/ai/plugins/:id/skills替换一个插件的技能
GET/ai/plugins/:id/tools列出插件的工具
POST/ai/plugins/:id/tools/prepare准备一次工具调用，等待批准
POST/ai/plugins/:id/tools/call执行已批准的工具调用
POST/ai/plugins/:id/tools/auto自动执行被允许的只读工具
POST/ai/plugins/:id/oauth/start开始连接托管 MCP 服务的 OAuth 流程，{web?: boolean}，返回 {url} 让用户在浏览器里打开
PUT DELETE/ai/plugins/:id/secret保存（{token}）或清除托管 MCP 服务的令牌或授权；只有使用令牌的服务才允许 PUT
GET/ai/plugins/grants列出对只读 MCP 工具的长期同意
PUT DELETE/ai/plugins/grants创建（{pluginId, toolName, mode:"always"}）或撤销（{pluginId, toolName}）长期同意；仅限浏览器会话（mcp_browser_session_required）

运行工具需要一个会话 id（浏览器会话，或 OAuth 令牌里的 sid），对 Bearer 客户端还需要 meo:write；客户端应在调用 tools/prepare 和 tools/call 之前自己弹出批准提示。每次写入类工具调用都需要一次性的批准。

GitHub 的 MCP 连接使用你已绑定的 GitHub 账号的令牌，只在服务端使用，不会返回给客户端；没绑定时返回 mcp_github_not_linked，令牌不可用时返回 mcp_github_reauthorization_required。

设备、配对和 Agent 运行

配对：设备只有在已登录的用户批准它的代码之后，才会得到凭据。

方法路径认证说明
POST/ai/device-enrollments/start无（边缘限流）开始配对，返回用户代码和一次性的设备密钥
POST/ai/device-enrollments/poll设备密钥pending → approved（凭据只返回一次）
GET/ai/device-enrollments/:code用户预览请求
POST/ai/device-enrollments/:code/approve用户批准配对

设备与运行：

方法路径说明
GET POST/ai/devices列出、登记设备元数据
GET/ai/workspaces自己设备上报的工作区
POST/ai/agent-runs创建一次运行
GET PATCH/ai/agent-runs/:id读取、变更状态
GET POST/ai/agent-runs/:id/events读取、追加运行事件

对话里的模型可以提议工作（work_agent_proposal），但永远不会自动派发一次运行。

用量

方法路径说明
POST/usage-events1–250 条一批，按 (source, source_event_id) 去重，返回 202 {accepted}
GET/usage-dashboard?days=days 为 7–730（默认 365）

用量是 AI 的 token 用量，字段见 Meo Account API。

实时

GET /realtime 升级为按账号的变更流，需要 meo:read。事件类型：memory.changed、settings.changed、projects.changed、files.changed，以及对话进行时的 run.delta。

还没有的

付款、结算页、客户门户和账单回调（Plus、Pro 目前是目录里的占位，结账未开放）；/v1/sync 同步流；对任何方案强制执行额度。
