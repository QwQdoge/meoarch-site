# MeoArch Site

The public umbrella website for MeoArch at `https://meoarch.org/`: what the project is, its products
(MeoArch OS, Meo AI, OmniStore, Meo Settings, MeoUI, Meo Login), how to install them (ISO, the Meo pacman
repository, AUR/yay once published), and a few other public projects.

The OS-specific site lives in the separate `MeoArch-os-webside` repository (`os.meoarch.org`).

| Path | Purpose |
| --- | --- |
| `index.html` | Page structure and content. |
| `styles.css` | Visual system and responsive layout. |
| `app.js` | Language switcher (zh-CN / en) and menu behavior. |
| `assets/` | Fonts (Comfortaa, Roboto Flex, SIL OFL), logo, and compressed product screenshots. |

## Local preview

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Open `http://127.0.0.1:8000/`. A local preview proves only local rendering, not hosting or deployment.

## Content rules

- Only claim what the product repositories and releases show; label states honestly (development preview, Beta, test ISO).
- Screenshots come from development builds; keep them compressed (WebP, about 1280 px wide).
- Both languages must stay in sync: every `data-i18n` key exists in `zh` and `en` in `app.js`.
- Install commands must match the Meo repository (`packages.meoarch.org`) and AUR packages that really exist.

## Project pages

Every project on the home page has two buttons: **Details** (its intro page on this domain) and **Open** (the project itself).

| Details URL | Served by |
|---|---|
| `/os/` | Worker `meoarch-paths` (`workers/paths`) proxying the OS site |
| `/ai/` | Worker `meoarch-paths` via service binding `meo-ai-landing` (root-absolute URLs rewritten to `/ai/...`) |
| `/vrc-m/` | Worker `vrc-m-intro` (source in the `vrcx-c` repo, `landing/`) |
| `/omnistore/`, `/meo-settings/`, `/meoui/`, `/meo-login/`, `/meokde/`, `/meo-repo/`, `/kde-widgets/` | generated by `python3 scripts/build_details.py`, committed here |

Add a project: add its card to `index.html` (two buttons), its text keys to `app.js`, and a row to `scripts/build_details.py` (or route an existing intro page).
Deploy the Worker with `cd workers/paths && wrangler deploy` (rollback = delete its routes). The site itself deploys on push to `main` through Cloudflare Pages.

## Updating docs and notices without a build

- **Our own docs** (`content/*.md`): edit the Markdown and push. The pages are pre-rendered, and `docs-live.js` draws the
  current `content/<name>.md` over them when a page opens, so no one needs to run `scripts/build_docs.py`. The `.md` of each
  page (`/docs/guide/<name>.md`, listed in `llms.txt`) is the same file through `_redirects`. A new document still needs one
  entry in `GUIDE_DOCS` and a run of the script, because the navigation is generated.
- **Update notice**: every site loads `https://meoarch.org/notice.js`, which shows one small notice from `notice.json`.
  Add an object to `notices` (`id`, `text.zh`/`text.en`, `label`, `href`, optional `sites`, `exclude`, `until`) and push.
  Closing it stores the id in a cookie on `.meoarch.org`, so it never appears again on any subdomain. Use a new `id` for
  each new notice. VRC Memories is excluded from Meo notices; give it its own entry with `"sites": ["vrc.meoarch.org"]`.
